# AI Workflow Skills

AI와 함께 제한 시간 안에 결과물을 만들면서 **판단 이유·검증 근거·본인의 이해**를 연결하는 한국어 Skill 4개입니다. 특정 도메인의 정답이나 완성 앱을 제공하지 않습니다.

## 무엇부터 쓸까

| 시점 | Skill | 남겨야 할 결과 |
|---|---|---|
| 시작·중요 요구 변경 | [clarify-work](skills/clarify-work/SKILL.md) | 목표, 필수 조건, 미확정 정책, 관찰 가능한 성공 기준 |
| 첫 실행·수정 후·제출 전 | [verify-with-evidence](skills/verify-with-evidence/SKILL.md) | 입력·기대·실제 결과, 실행 근거, 미검증 범위 |
| 중단·맥락 정리·인계 전 | [handoff-work](skills/handoff-work/SKILL.md) | 현재 상태, 결정 이유, 검사 결과, 다음 행동 |
| 핵심 기능 완료·제출 전 이해 확인 | [explain-your-work](skills/explain-your-work/SKILL.md) | 설계·검증 기록, 사용자가 직접 설명한 판단·사례·한계와 피드백 |

처음부터 네 개를 전부 읽히거나 매 단계 긴 문서를 만들 필요는 없습니다. 지금 필요한 Skill만 적용합니다. 일반 작업에는 외부 계정·MCP·Plugin·추가 모델이 필요하지 않습니다. 판정·계산을 실행 중 AI에 의존하도록 요구하지 않습니다.

## 권하는 작업 흐름

1. **시작:** `clarify-work`로 README의 필수 조건과 모호한 정책을 정리하고 첫 실행본을 만든다.
2. **구현·검증:** `verify-with-evidence`로 작은 입력의 기대 결과와 실제 결과를 대조한다. 중요한 결정은 기존 과제 문서에 기본 3개 이내로 모으고 관련 검사 기록을 연결한다.
3. **이해 확인:** `explain-your-work`를 첫 실행 성공·핵심 기능 검증 완료·제출 준비 시점에 적용한다. 질문 하나에 본인이 먼저 답하고 AI가 실제 코드와 대조한다. 시점별 2~3분은 권장 안배이며 공식 규칙이 아니다.
4. **제출 전:** 실제 파일과 문서의 모순·필수 누락을 먼저 확인한다. 구현에 근거한 연습 질문 6개 중 설명이 취약한 3개를 우선하며 필수 검증·제출 시간을 확보한다. 6문항×5분의 전체 모의는 시간 여유가 있는 사전 연습에서 별도로 진행한다.

과제에서 지정한 설계·테스트·협업 문서가 있으면 그대로 활용합니다. 별도 기록이 필요할 때만 `DESIGN_DECISIONS.md` 하나로 모을 수 있으며 고정 제출 양식은 아닙니다. 실제 선택 이유·대안·구현 위치·검증·한계와 본인/AI의 역할을 연결하고, 코드가 바뀌면 기록도 확인합니다. 중단·대화 전환이 필요할 때만 `handoff-work`를 추가합니다.

## 바로 시작하기

Skill을 설치한 개인 연습 환경에서는 다음처럼 요청합니다.

```text
$clarify-work README와 제공 자료에서 필수 조건과 미확정 정책을 정리해 줘.
$verify-with-evidence 현재 결과를 실제 입력·출력으로 확인하고 미검증 부분을 알려 줘.
$handoff-work 다음 대화에서 이어갈 수 있도록 현재 상태와 다음 행동을 정리해 줘.
$explain-your-work 내가 먼저 설명할 테니 구현과 근거를 대조해 질문해 줘.
```

작업 중 기록부터 함께 적용하려면 다음처럼 요청합니다.

```text
$explain-your-work 중요한 설계 결정과 검증 근거를 기존 과제 문서에 짧게 기록해 줘. 첫 실행 성공, 핵심 기능 검증 완료, 제출 준비 때 질문 하나씩 하고 내 답을 실제 코드와 대조해 줘. AI가 작성한 이유와 내가 직접 판단·확인한 사실을 구분해 줘.
```

제출물 확정 전에는 다음처럼 요청합니다.

```text
$verify-with-evidence 실제 제출 대상에서 필수 누락, 코드·문서 모순, 근거 없는 완료 주장을 확인해 줘.
$explain-your-work 현재 구현과 기록에 근거한 독립 연습 질문 6개와 근거 위치를 짧게 제시해 줘. 설명이 취약한 3개를 우선하고 모범답안보다 내 답을 먼저 받아 대조해 줘.
```

설치하지 않은 경우에는 해당 `SKILL.md` 경로 또는 공개 URL을 지정해 읽고 적용하도록 요청할 수 있습니다. 링크를 전달한 것만으로 설치·자동 적용됐다고 판단하지 말고, 실제로 읽었는지 확인합니다.

## 설치와 공개 저장소 활용

공개 저장소 주소: `https://github.com/nameUser-byte/ai-workflow-skills`

로컬 연습용 Codex에서는 `$skill-installer`에 이 저장소의 필요한 Skill 경로만 설치해 달라고 요청합니다. 예를 들어 `skills/verify-with-evidence`입니다. 또는 작업 프로젝트의 `.agents/skills/` 아래에 필요한 Skill 폴더를 복사할 수 있습니다. 이 저장소는 별도의 Plugin이나 자동 설치 프로그램을 포함하지 않습니다. 설치 위치와 적용 상태는 실제 환경에서 확인하세요. [OpenAI 공식 Skill 안내](https://learn.chatgpt.com/docs/build-skills)

제한된 평가 환경에서 참고할 때는 먼저 그 환경의 규칙을 확인합니다. 공개 자료의 다운로드가 허용된 경우에만 플랫폼 내부의 AI에 공개 저장소 URL을 전달하고 필요한 Skill을 가져와 읽도록 요청합니다. 공개 자료의 허용 조건은 해당 운영 안내를 따르며, 이 저장소는 작성자나 공개 시점에 따른 별도 제한을 임의로 추가하지 않습니다. 개인 PC 파일 업로드 제한이나 차단을 다른 경로로 우회하지 않습니다.

AI 사용이 금지된 후속 평가 단계에서는 이 Skill을 포함한 AI 도움을 중단합니다. 본인이 이해하고 기억한 내용으로 직접 답변합니다. 실제 시험 문제·제출물·작업 기록을 외부로 보내지 않습니다.

## 기억할 질문

핵심 기능에 대해 **어떤 입력과 기준으로 결정하는지 → 다른 방식을 쓰면 무엇이 달라지는지 → 실제 사례 하나가 무엇인지**를 설명하세요.

비율을 설명할 때는 **어떤 집단인지 → 몇 개 중 몇 개인지 → 동시에 달라진 조건은 무엇인지**를 포함하세요.

기록에는 **선택과 이유 / 실제 검사와 관찰 결과 / 남은 한계와 다음 확인**을 남깁니다. AI가 작성한 문서가 본인의 이해를 증명하는 것은 아닙니다. 연습에서는 본인이 먼저 말하고 근거와 대조합니다.

문서로 실제 출제 문항을 고정할 수 있다고 가정하지 않습니다. 자신 있는 설계 결정도 사실대로 적고, 실제 검증·한계·협업 경위까지 설명할 수 있는지 확인합니다.
